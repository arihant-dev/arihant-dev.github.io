Raft by Hand

September 2, 2026

For a distributed systems hackathon I built a replicated key-value store on a Raft implementation I wrote myself, and the toolkit that grades it. The grader runs a chaos agent next to three nodes: it partitions the network, kills nodes, and floods them with writes, then checks that no acknowledged write was lost.

The paper reads cleanly. The code does not. Most of the time went into the edges: persisting hard state before replying, a write-ahead log that survives a container being recreated (not only restarted), and elections that settle instead of splitting the vote forever. Source: distributed-kvstore.

Joining Prelude

August 2026

In August I joined Prelude in Paris as a Software Engineer Intern. Prelude verifies users and delivers messages over SMS, WhatsApp, Viber and RCS.

Telecom turns out to be a distributed system you do not own. Every provider is a node with its own API, its own failure modes, its own idea of a delivery receipt, and its own price list in its own format. Most of my work so far sits on those boundaries: provider integrations, pricing data, and checking in production that a change did what it should.

Understanding Map Reduce & The 1 Billion Row Challenge

December 10, 2025

Recently, I've been diving deep into distributed systems and came across the fascinating concept of Map Reduce. It's a programming model and an associated implementation for processing and generating big data sets with a parallel, distributed algorithm on a cluster.

Inspired by the 1 Billion Row Challenge hosted on GitHub, I decided to implement a simplified version of Map Reduce for a side project. The goal was to process a massive dataset efficiently by splitting the work across multiple nodes (Map phase) and then aggregating the results (Reduce phase).

My understanding was greatly enhanced by the MIT 6.824 Distributed Systems Lecture 1 and the Map Reduce paper by Jeffrey and Sanjay, which provides a rigorous theoretical foundation for such algorithms. Implementing this gave me hands-on experience with data partitioning, shuffling, and handling node failures in a distributed environment.
